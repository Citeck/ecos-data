# Доказательство: сравнение связей в матрице ловит подмену, которую счётчик пропускал

Дата: 2026-09-17. Ветка `fix/COREDEV-501-review`, HEAD `34818bb`
(`COREDEV-501 - Compare the associations a migration carried, not how many there were`).

## Что проверялось

`DbConversionMatrixTestBase.recoverableLinkCount` (только число связей) заменён на
`recoverableLinks`, сравнивающий список `LinkSnapshot(targetId, index, child, created, creator)` в
порядке `__index` с тем же снимком, снятым **до** смены типа. Утверждение, которое надо было
доказать, а не заявить: новая проверка падает на подмене связи **при неизменном их количестве**.

Подмена одиннадцатой связи — не произвольный выбор. Колонка assoc-подобного атрибута кэширует ровно
первые десять target id (`ASSOC_COLUMN_CACHE_SIZE`), поэтому одиннадцатая связь невидима и для
сравнения физического значения бэкапа, и для любого утверждения, читающего атрибут через колонку.
Фикстура матрицы держит `0..ASSOC_COLUMN_CACHE_SIZE`, то есть 11 связей.

## Инъекция

Временная обёртка над `recoverableLinks`: если связей больше десяти, у элемента с индексом `10`
подменяется `targetId` (`+1000`); количество, порядок, `__index`, `__child`, `__created`,
`__creator` остаются прежними. Инъекция не коммитилась и откачена сразу после прогонов.

## Результат

| прогон | PostgreSQL | in-memory |
|---|---|---|
| с инъекцией | **188 тестов, 5 падений** | **188 тестов, 5 падений** |
| после отката | 188 / 0 падений | 188 / 0 падений |

Падают одни и те же пять случаев на обоих бэкендах (`[74]`, `[75]`, `[76]`, `[77]`, `[142]`):

- `ASSOC -> TEXT`, `ASSOC -> MLTEXT`, `ASSOC -> NUMBER`, `ASSOC -> ENTITY_REF` — связи припаркованы
  в `ed_associations_backup` под реестровой строкой ушедшей в бэкап колонки;
- `ASSOC -> ASSOC` (сужение арности `multiple -> single`) — атрибут остаётся assoc-подобным, связи
  остаются живыми в `ed_associations`.

То есть инъекция ловится на **обеих** ветках `recoverableLinks`, а не только на той, что читает
бэкап.

Само сообщение о падении показывает, почему счётчик был слеп (сокращено):

```
expected:
  [... LinkSnapshot(targetId=12, index=9, ...),
      LinkSnapshot(targetId=13, index=10, ...)]
 but was:
  [... LinkSnapshot(targetId=12, index=9, ...),
      LinkSnapshot(targetId=1013, index=10, ...)]
```

Одиннадцать элементов с обеих сторон, различие ровно одно. `recoverableLinkCount` вернул бы `11 == 11`
и прошёл бы.

Внутри `assertAll` сработало ровно одно утверждение из трёх — ни сравнение физического значения
бэкапа, ни проверка значения после смены типа подмену не заметили. Это и есть цена, которую новая
проверка покрывает, и подтверждение, что она не дублирует существующие.
