# Ревью COREDEV-501, 2026-09-17

Проверен коммит `55d466c81c370c83114a59fd758a70e08f5689b3` в ecos-data; дополнительно просмотрены связанные изменения подписки на события в ecos-model-lib и ecos-webapp-commons. Production-код не изменён.

## P1: Restart заменённой задачи удаляет действующие связи

`DbBatchTaskService.restart` разрешает запуск любой финальной задачи, включая автоматически отменённую следующей миграцией. `DbColumnMigrationHandler.prepare`, строка 100, выполняет уход из группы ассоциаций по сохранённым параметрам без проверки актуальности миграции. Даже проверка существования исходной backup-колонки выполняется позже.

Воспроизведение: создать ASSOC[] со связью; изменить на TEXT[], не запускать перенос; вернуть ASSOC[]; перезапустить автоматически отменённую задачу ASSOC[] → TEXT[]. Связь, присутствующая перед запуском, удаляется из ed_associations. Тест получил `[]` вместо `[2L]`.

Нужно отличать заменённые задачи от возобновляемых и проверять идентичность/поколение исходной и целевой колонок до любых побочных эффектов обработчика.

## P1: Восстановление связей отменяет выбор пользователя

`DbColumnMigrationHandler.restoreAssocsOfWindow`, строки 843–847, безусловно добавляет сохранённые связи. Проверка непустой целевой колонки применяется позже, только к переносу значений, и не защищает восстановление ассоциаций.

Воспроизведение: ASSOC[] со связью A → TEXT[] с завершённым переносом → ASSOC[]; до фонового восстановления пользователь записывает B. Перед переносом ed_associations содержит только B, после — B и A. Тест получил `[4L, 2L]` вместо `[4L]`. Это непустое пользовательское значение, а не осознанно принятый в спецификации случай очистки в NULL.

Нужно различать восстановленный кеш колонки и последующую пользовательскую правку и не поднимать прежние связи поверх такой правки; решение должно учитывать конкурентные мутации.

## P2: Матрица не проверяет целостность бэкапа

`DbConversionMatrixTestBase.assertOriginalIsRecoverable`, строки 429–462: для скаляра проверяется только `isNotNull`, для массива — число элементов, для ассоциаций — число связей. Подмена содержимого при сохранении размера проходит.

Проверено внесением ошибки в фикстуру: после переноса TEXT → NUMBER, перед штатными assertions, исходный backup `text` заменён на `CORRUPTED`. Отдельная проверка подтвердила запись подмены. Все 156 случаев `everyChangeIsMigratedAsTheMapPromisesTest` на in-memory прошли. Вывод — `review-matrix-fault.log`. Исходный тест восстановлен побайтно и повторно скомпилирован: 156/156 прошли (`review-matrix-restored.log`); `git diff` исходников пуст.

Нужно сравнивать исходное и сохранённое физическое значение целиком, включая порядок элементов; для связей — target id и метаданные. Это пробел именно матрицы, не утверждение о бесполезности всего набора: отдельные round-trip тесты сравнивают реальные значения, а PostgreSQL-тесты сопоставляют два независимых пути конверсии. Unit-тесты классификации задают ожидаемые классы явно, поэтому использование классификатора матрицей само по себе не делает весь набор тавтологией.

## Документация: требуется сокращение и исправление утверждений

- `DbShadowColumnTransition.kt`: 201 строка комментариев из 405; `DbBatchTaskEngine.kt`: 405 из 1069. Повторяются обоснования порядка операций, история прежних исправлений и пересказ соседнего кода. Оставить контракт, ограничения транзакций/блокировок и нетривиальные инварианты; историю разработки убрать.
- `DbColumnValueConverterTest.kt:19`: рассказ о «трёх раундах ревью» не помогает понять тест. Достаточно перечислить проверяемые свойства и границы фикстуры.
- `DbColumnRestore.kt:123`: «Three renames» неверно — два переименования и обновление метаданных.
- `DbModelChangeQueue.kt:232`: обещание возвращать незавершённую работу во всех случаях неверно: обычная ошибка reconciliation логируется и не ставится обратно в очередь. Описать реальную retry-политику без абсолютных гарантий.
- Локальные планы и спецификация занимают 13 513 строк, включая отменённый DRAFT. Они исключены из Git через `docs/superpowers`, поэтому это не размер документации коммита. Их не следует выдавать за актуальное руководство; для сопровождения нужна одна краткая документация текущего поведения.
